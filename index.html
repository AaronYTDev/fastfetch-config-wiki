fastfetch-config

A CLI tool to manage your fastfetch configuration with ease.

This wiki reflects V1.6.7.

What is it?

fastfetch-config is a command-line utility that lets you manage every aspect of your fastfetch config — modules, logos, image rendering, OS names, colors, backups, and more — without editing JSON files by hand.

Features

  • Add, remove, reorder, toggle, and configure modules (title, os, host, kernel, etc.)
  • Set logos from built-ins, local files, bundled ASCII art, or auto-detection
  • Browsable Logo Gallery with previews and one-key apply
  • Chafa image rendering, auto-fitted to your terminal size
  • Spoof the displayed OS name — or pick a random one from 100+ distros
  • Configure logo colors by slot: 150+ named colors, raw hex, or ANSI codes
  • Full backup & restore system with pruning (clean) and diff support
  • Export / import configs as portable files
  • Self-update directly from GitHub releases (stable or prerelease)
  • Diagnostics: doctor, diag, and search
  • Interactive TUI menu for point-and-shoot configuration

Quick Start

bash install-ff.sh
ff tui

Installation

Prerequisites

  • fastfetch — the system info tool (must be installed separately)
  • jq — JSON processor (required; installed automatically if missing)
  • chafa — terminal image rendering (installed automatically if missing)
  • ImageMagick — installed automatically if missing
  • bash & standard Unix utilities

Installing

Download install-ff.sh and run it:

bash install-ff.sh

The installer will:

  1. Detect your distro (via /etc/os-release or lsb_release)
  2. Install missing dependencies with your package manager
  3. Install the fastfetch-config script to ~/.local/bin/
  4. Create the ff alias script
  5. Set up a default config at ~/.config/fastfetch/config.jsonc
  6. Install bundled ASCII art logos to ~/.config/fastfetch/logos/
  7. Add ~/.local/bin to your PATH (bash, zsh, or fish)

Supported Distros

The dependency installer supports Arch-based (Arch, CachyOS, EndeavourOS, Garuda, Manjaro), Debian/Ubuntu-based (Ubuntu, Debian, Pop!_OS, Mint, elementary), Fedora/RHEL, openSUSE, Alpine, Void, and Gentoo. On unknown distros it prints a reminder to install jq, chafa, and imagemagick manually.

Preserving Your Existing Config

By default, the installer overwrites any existing config. To keep yours:

bash install-ff.sh -nodelete

Sudo Password

The installer prompts for sudo only when installing missing packages. The script itself runs without root.

Updating

The tool ships with a built-in updater that pulls the latest installer from GitHub releases:

ff update                    # download and install latest stable
ff update check              # check for stable updates only
ff update -prerelease        # install latest, including prereleases
ff update check -prerelease  # check for any updates, including prereleases

A quiet background check runs at most once per day (when you launch the TUI or run ff); if a newer version exists it prints a one-line notice.

You can always reinstall manually by downloading and running install-ff.sh again, and ff version shows what you're currently on.

The modules submenu shows the current module list at the top and offers:

  • Add — insert a module at its default position
  • Remove — delete a module by name
  • Move — reorder a module to a new position

  • Easy set — set both the display label (key) and format in one step

  • List backups
  • Restore backup
  • Remove backup

  • Reset entire config — a pre-reset backup is saved automatically

Each operation pauses with Press enter to continue... so you can read the result before the screen refreshes.

Modules

Modules are the building blocks of your fastfetch display. Each module corresponds to a piece of system information. Manage them with ff module ... (the legacy alias ff var ... still works).

Default Order & Positions

PositionModuleNotes
0title
1separator
2osBecomes {type:"custom", key:"OS", format:"..."} when renamed
3host
4kernel
5uptime
6packages
7shell
8de
9wm
10cpu
11memory
12swap
13gpu
14diskDefaults to {type:"disk", folders:"/"}
15locale
16break
17colors

New modules added with ff module add are inserted at their default position when one is defined; otherwise they're appended to the end.

Module States

A module can be either:

  • String — simple name like "kernel"
  • Object — enriched form with custom keys, e.g. {"type":"disk","folders":"/"}

When you set a property on a string module, it automatically converts to an object. The reset command reverts an object back to its default form, and ff module reset all resets every known module at once.

Toggling & Inspecting

ff module toggle gpu     # remove if present, add if missing
ff module show disk      # print the module's JSON

Logo

fastfetch-config supports several logo sources:

Auto-detection

ff logo auto

Restores automatic logo detection based on your distro.

Built-in Logos

ff logo arch
ff logo ubuntu
ff logo fedora
ff logo steamos

Use any name from fastfetch --print-logos. List them all with ff list-logos, which also shows the contents of your custom logos directory.

Bundled ASCII Art Logos

ff logo install    # installs: dragon sword robot cat pacman dog bear wolf
ff logo dragon

These are copied into ~/.config/fastfetch/logos/.

Custom File

ff logo ~/my-logo.txt
ff logo my-custom

Provide a path to a file, or a name that matches a file in ~/.config/fastfetch/logos/. Files are copied into the logos directory automatically on first use. Image files (png, jpg, gif, webp, bmp, tiff) automatically switch the logo to chafa mode.

Fitting & Dimensions

ff logo fit            # recalculate size for the current terminal
ff logo width          # show current width
ff logo width 40       # set width manually
ff logo height 20      # set height manually
ff logo preview        # show logo type, source, and dimensions

fit measures your terminal and the rendered output, clamping sizes to sensible ranges. Text logos are fitted by line height; chafa logos by both width and height. Fitting happens automatically whenever you change the logo or toggle chafa.

Logo Gallery

ff gallery

A paginated browser (15 per page) for every built-in logo:

  • Type a number to preview that logo full-size, then press y to apply it
  • n/p — next / previous page
  • / — filter by name substring
  • r — reset filter
  • q — quit

Applying a logo from the gallery runs it through the same fitting logic as ff logo.

Chafa (Image Logos)

Chafa renders real images (PNG, JPG, GIF, WebP...) directly in your terminal as colored character art. It requires the chafa package, which the installer sets up for you.

Chafa is disabled by default. Enable it with:

ff chafa on

Modes

ModeDescription
onStandard chafa rendering
rawChafa raw mode — output passes straight through to the terminal
offDisable chafa and revert to auto logo detection

Using an Image

ff chafa on ~/Pictures/wallpaper.png   # enable with an image
ff chafa raw ~/Pictures/wallpaper.png  # raw mode with an image
ff chafa off                           # back to auto logos

Passing an image copies it into ~/.config/fastfetch/logos/ and points the config at it. Setting an image file via ff logo <file> enables chafa mode automatically.

Fitting to Your Terminal

ff chafa fit    # re-measure the terminal and resize the logo

Fitting accounts for the width of your fetch output so the info columns never overlap the image. It runs automatically when toggling chafa or changing the logo; resize your terminal and run ff chafa fit to adapt.

When chafa is active, plain ff launches fastfetch with --pipe false so colors render correctly.

OS Name

Override the displayed operating system name:

ff osname "SteamOS holo 3.7.25 (steamdeck) x86_64"
ff osname auto

When you set a custom OS name, the os module is transformed into a custom module with key: "OS". Running ff osname auto restores the default os module with auto-detection.

Random Spoofing

ff osname random

Picks a surprise OS name from a pool of 100+ entries — everything from Arch Linux and FreeBSD to TempleOS, Windows 98, Haiku, Plan 9, and KolibriOS.

OS Name + Logo Combo

ff osname-logo "MyOS 1.0"       # sets both OS name and logo to "MyOS 1.0"
ff osname-logo "MyOS" arch      # OS name "MyOS", logo "arch"

Colors

Override specific logo color slots (1–9):

ff color 1 blue
ff color 2 93
ff color 3 orange
ff color 4 #FF8000
ff color 5 skobeloff
ff color list
ff color reset

Supported Color Values

  • Named colors — 150+ built-in names: red, orange, gold, emerald, lime, pink, crimson, coral, indigo, mint, pearl, silver, diamond, skobeloff, purple, charcoal, denim, sapphire, wine, copper, and many more
  • Raw hex codes — e.g. #FF8000
  • ANSI codes — 32, 93, 208, etc.

Finding Names

ff color names           # list every supported name
ff color search pur      # find names containing "pur"

Note: The orange color is mapped to hex #FF8000 because ANSI 208 appeared as white on some terminals.

Backup & Restore

Save and restore your entire fastfetch configuration.

Creating Backups

ff backup                  # timestamp-based name
ff backup my-config        # named backup

Backups are stored as .jsonc files in ~/.config/fastfetch/backups/. Overwriting an existing backup name asks for confirmation first. A pre-reset backup is taken automatically before ff reset, and a pre-import backup before ff import.

Listing Backups

ff backup list

Shows each backup with its creation date.

Restoring

ff restore my-config

Copies the backup back to config.jsonc, overwriting the current config.

Removing Backups

ff backup rm my-config
ff backup remove my-config

Cleaning Old Backups

ff clean         # remove backups older than 30 days
ff clean 7       # remove backups older than 7 days

Diffing Against a Backup

ff diff                # compare against the most recent backup
ff diff my-config      # compare against a specific backup

Export & Import

ff export my-config.jsonc    # copy config anywhere
ff import my-config.jsonc    # bring it back (auto-backup first)

TUI Backup Menu

From the main TUI menu, select 9) Backup / Restore (or press b) to access create, list, restore, and remove options.

Updating

fastfetch-config updates itself straight from GitHub releases.

ff update                    # download + install latest stable
ff update check              # just check, don't install
ff update -prerelease        # install latest, including prereleases
ff update check -prerelease  # check including prereleases

What happens on update?

  1. The tool queries the GitHub API for the latest release
  2. Compares it against your installed version (ff version)
  3. Shows the changelog from the release notes
  4. Asks for confirmation, downloads install-ff.sh and runs it

Prerelease Channel

Prereleases are versions tagged with -prerelease. They're skipped by default; opt in per-command with the -prerelease flag. Once you're on a prerelease build, plain ff update keeps following the prerelease line until a stable release catches up.

Quiet Update Check

Whenever you run a command, fastfetch-config silently checks GitHub at most once per day. If something new is out you'll see a one-line notice:

[update] Version V1.6.8 available! Run 'ff update' to install the latest build.

Troubleshooting

Built-in Checks

ff doctor        # pass/fail report of common issues
ff diag          # full environment dump

doctor verifies jq, fastfetch, config validity (must be real JSON), and that the logos & backups directories exist. diag prints versions, paths, module list, current logo, OS name, chafa state and shell/terminal info — everything useful for a bug report.

Common Issues

SymptomFix
ff: command not found after install~/.local/bin isn't on your PATH yet — run source ~/.bashrc (or open a new terminal)
jq is requiredInstall jq with your package manager (e.g. sudo pacman -S jq)
Installer says "Unknown distro"Install jq, chafa and imagemagick manually, then re-run the installer
Config errors / invalid JSONff restore <backup> or ff reset; verify with ff doctor
Logo wrong size after resizing terminalff logo fit (or ff chafa fit for images)
Image renders oddly in some terminalsTry raw mode: ff chafa raw
Made a mess?ff backup before-tweaks before experimenting next time; ff reset gets you back to defaults

Still stuck?

Run ff diag and open an issue at github.com/aaronYTDev/fastfetch-config/issues with the output attached.

Backup Workflow

# Before making changes
ff backup before-tweaks

# Make your changes...

# See what changed since the backup
ff diff before-tweaks

# If something goes wrong
ff restore before-tweaks

# Housekeeping
ff clean 14       # drop backups older than two weeks

Troubleshooting

ff doctor    # verify jq, fastfetch, config validity, directories
ff diag      # full environment dump: versions, paths, current settings
ff search d  # find anything matching "d" across modules and colors

Minimal Config Reset

# Reset everything (auto-backup first)
ff reset

# Reset just one module
ff reset colors
